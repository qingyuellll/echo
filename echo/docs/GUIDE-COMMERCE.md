# Echo 购票与评测助手对接

导购位于 `D:\echo-shopping-guide`，Echo 用户端 `D:\echo\user`，后端 `D:\echo\echo`。

## 使用流程

1. 在导购 `http://127.0.0.1:8082` 浏览演出、比较口碑或咨询选票。
2. 推荐票档或演出详情的票档中点击“确认订单”，进入 Echo `http://127.0.0.1:3002/guide/checkout/{ticketId}`。未登录时先登录，再返回原确认页。
3. 用户核对演出、最新票档价格、数量、规则；需要座位的票档在此选座。勾选确认后才创建订单。普通票复用普通/选座订单服务，秒杀票复用原队列，支持继续查询排队状态。
4. 订单生成后进入原付款页，由用户单独确认付款。Echo 当前为模拟支付，不代表已接通微信、支付宝真实扣款。
5. `http://127.0.0.1:3002/guide` 提供购票进度与评测入口，原个人中心的已支付/已核销订单也增加评测入口。
6. 在评测编辑页由用户主动选 1–5 星，可仅评分。需要整理文字时填写自己的真实感受，生成可编辑草稿；草稿只有填入编辑区、核对并确认发布后才进入 Echo 公共评测。发现已有评测时提供原文链接，不继续创建重复内容。

## 接口与边界

新增接口均位于 `/guide`，沿用 Echo 的登录拦截器和 CSRF 校验，不向导购暴露用户令牌：

- `GET /guide/checkout/{ticketId}`：确认页数据，返回演出、票档、权威原价（分）、可购状态与模拟支付标记。历史或下架演出被拒绝。
- `POST /guide/orders/{ticketId}`：必须包含 `confirmed:true`、`requestId`、`count`、`expectedUnitPrice` 和 `seatIds`。服务端再次校验演出、票价和选座数量，并交给原订单服务校验库存、归属与锁座。票价变化需重新确认，不使用前端传入金额计价。
- `GET /guide/requests/{orders|reviews}/{requestId}`：查询同一用户同一次提交的结果。
- `GET /guide/reviews/context/{showId}`：只查询当前登录用户的购买/核销状态和已有评测编号。购买记录用于辅助提示，不改变 Echo 原有评测资格规则，不把未核销的订单标为已观演。
- `POST /guide/reviews/draft`：接收演出、用户选择的评分和用户自己的笔记，转发到导购的文字草稿服务；转发不带用户登录令牌。不参考其他观众评测代写个人经历，也不发布。
- `POST /guide/reviews`：必须明确确认后发布；只接收可编辑字段，作者由 Echo 的原评测服务按登录用户填写。

`GuideActionExecutor` 使用 Redis 按用户、动作与请求编号保存请求内容摘要及结果 24 小时。重复点击同一内容返回同一结果，内容改变时拒绝复用编号。执行结果不确定时保留处理中状态，前端引导查询订单/评测，避免自动重复写入。写入前 Redis 不可用时不会执行订单或发布操作。原服务的库存和一人一演出一次评测规则继续生效；该机制不代替现有交易事务和库存原子校验。

咨询和草稿模型只负责准备信息，不执行订单、付款、评分或发布。模型不可用时草稿保留用户原话，标记为笔记整理；评分不自动预设五星。

## 构建、运行与配置

- 后端：`mvn -DskipTests package`。运行中的 Windows JAR 应先停止再替换；开发环境可使用 `mvn -f guide-build.pom.xml -DskipTests package` 生成独立更新包，避免覆盖运行文件。
- 根目录 `start-guide-backend.cmd` 使用标准的 `target/echo-0.0.1-SNAPSHOT.jar` 启动 8081，同时提供当前 Windows Java 本地网络兼容设置。数据库、Redis 和 RocketMQ 保持原配置。
- 用户端：`npm run build`。当前环境限制子进程管道时，`npm run build:direct` 先用 Vue 编译器处理模板与作用域样式，再通过 esbuild 可执行程序打包，同样先进行 Vue/TypeScript 检查。临时编译文件在系统临时目录中清理。
- 用户端生产预览：`npm run preview:direct` 或 `start-guide-user.cmd`，地址 3002，`/api` 代理到 8081，页面采用原有登录态与路由。
- 导购仍使用原来的 `start-guide.cmd`，地址 8082。
- Echo 后端配置项 `echo.guide-base-url` 默认 `http://127.0.0.1:8082`，只用于评测草稿转发。导购的 `ECHO_WEB_BASE` 默认 `http://127.0.0.1:3002`；用户端可用 `VITE_GUIDE_URL` 指定导购首页地址（标准 Vite 构建）。

## 验证

新增 18 项 Java 测试通过，覆盖订单确认与输入限制、票价变化、历史场次、座位数量与重复座位、普通/秒杀/选座分流、重复请求、异常后查询、用户隔离、评测字段和评分校验。测试以替身服务验证写入行为，不创建真实订单或评测。

导购 Go 全部测试通过，包括草稿保留用户笔记、拒绝缺失评分与内容；两边前端类型检查和生产打包通过。实际验证了 Echo 健康状态、3002 的工作台/确认页/评测页/付款页、静态入口资源、API 代理、登录拦截和导购票档链接。未使用用户账号进行真实下单、付款或公开发布；尚未完成浏览器交互与手机截图验证。
